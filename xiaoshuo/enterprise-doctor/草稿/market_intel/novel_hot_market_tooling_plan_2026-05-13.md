# novel_hot_market_tooling_plan_2026-05-13

状态：本文件是小说行业信息采集流程落地计划；当前不登录、不绕过、不批量抓取、不搬运正文。用途是把四类工具能力转化为《enterprise-doctor》的热点/爆款/竞品只读采集流程。

## 0. 总原则

- 只读公开信息：公开网页、公开榜单、公开评论、公开作者访谈、公开视频字幕、公开 GitHub 仓库。
- 不抓付费章节，不绕登录，不采集用户隐私，不保存 cookie/token。
- 不复制爆款剧情，不改名套用，不搬运正文。
- 所有市场结论分三类：
  - REAL_PUBLIC：有公开URL/截图/时间戳。
  - BOSS_BACKEND：老板提供截图/导出。
  - SIMULATED：内部推演，禁止冒充真实平台数据。
- 市场反馈只用于第28章以后和未来章节写法调整，不回改已发布1-27章主线。

## 1. 公开网页搜索与提取

用途：
- 合规搜索小说榜单：番茄、七猫、起点等公开榜单。
- 观察热门题材：都市、现实、经营、创业、小店、餐饮、欠债、老板、系统/非系统差异。
- 拆爆款标题：短句、反差、职业钩子、痛点词、强承诺。
- 提取读者评论关键词：爽/慢/水/说教/真实/上头/弃文原因。
- 观察公开页面趋势：榜单位置、简介表达、章节标题节奏。

落地到本书：
- 第28章写法参考：公开趋势中“反差标题 + 即时危机 + 现实痛点”更能抢注意力；所以第28章不写流程说明书，而写“短视频剪辑把小店第一天试点逼成公开事故”的即时危机。
- 不搬运任何具体作品剧情，只使用结构方法：开头先事故，中段多次反转，结尾倒计时。

记录字段：
- source_url
- source_title
- platform
- capture_time
- observation
- applied_to_chapter
- evidence_type：REAL_PUBLIC / BOSS_BACKEND / SIMULATED

## 2. 复用 Chrome / 直接操控浏览

用途：
- 可复核打开公开榜单页面。
- 截图留证。
- 记录页面标题、URL、抓取时间。
- 对公开评论做小样本人工摘录。

边界：
- 不绕过登录。
- 不抓隐私。
- 不保存 cookie/token。
- 不自动操作发布后台。
- 如进入草稿箱，也只能在老板授权的子账号/最小权限下编辑草稿，不点发布。

落地到本书：
- 后续每次市场采集形成 `market_intel/YYYY-MM-DD_public_sources.md`。
- 每条结论必须带证据路径或截图路径；无证据则标 SIMULATED。

## 3. YouTube 字幕 / GitHub / 视频分析 / 代码理解

用途：
- 提取公开视频里关于网文写作、爆款拆解、作者访谈、平台规则解读的字幕。
- 学习公开 GitHub 中的写作工具、爬虫、文本分析工具、章节钩子检测方法。
- 视频分析只做方法拆解：节奏、钩子、反转、爽点密度、章节标题，不搬运内容。
- 代码理解只读学习，不直接运行未知爬虫抓平台。

落地到本书：
- 形成“爆款拆解卡”：
  - 5秒开头钩子
  - 1000字内反转
  - 现实痛点
  - 主角动作
  - 章末未解问题
- 第28章采用“公开舆情危机 + 明早验收倒计时 + 证据反击”的结构，不采用别书剧情。

## 4. 复杂操作 / 表单填写

用途：
- 未来平台发布表单填写前的检查清单。
- 检查标题、简介、章节正文、标签、敏感词、章末钩子、错别字、字数。
- 生成待发布清单。

禁止：
- 不能自动发布。
- 不能点发布按钮。
- 不能改线上已发布正文。
- 不能改作者资料、签约、收益、银行卡、提现。
- 不能删除章节/评论/数据。

落地到本书：
- 每章发布前必须有：字数≥3500、xiaochan gate、必要时 xiaofa、格式检查、人工复查建议。
- 发布表单最多辅助填写草稿，必须由老板人工最终确认发布。

## 5. 第28章本轮采用的市场/爆款参考

证据类型：SIMULATED_METHOD / 非实时公开采集。
说明：本轮未直接登录或抓取平台；采用的是公开网文通用爆款结构方法，不冒充真实平台数据。

参考结论：
1. 标题/开头要有现实痛点和即时事故，而不是先讲背景。
2. 章节内至少两次反转：舆情剪辑压迫 → 证照/流程反击 → 临时验收倒计时升级。
3. 爽点要可视化：不是“林川讲对了”，而是“他当场让对方的剪辑失效、让小店有上桌资格”。
4. 章末钩子要有倒计时和不可回避后果：明早验收不过，第一批员工现场取消，小店直接社会性死亡。
