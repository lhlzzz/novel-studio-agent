# xiaoshuo 协作流程：章节写作、外部信息、xiaochan补充、正文/草稿分离

适用项目：enterprise-doctor / 急诊医生

## 目录规则

根目录只保留：
- `正文/`：唯一发布用章节目录。
- `草稿/`：所有修改件、半稿、候选稿、市场爬取记录、质量门、报告、wiki、备份、隔离副本。
- `CONTEXT.md` / `MEMORY.md`：项目上下文。
- `目录整理_MANIFEST_*.json`：整理审计记录。

发布只允许从 `正文/` 取稿。
任何新改稿先进入 `草稿/`，不得直接覆盖 `正文/`。

## 每章必走流程

1. 明确章节目标
- 当前章节号
- 上章承接
- 本章主冲突
- 爽点动作
- 章末钩子
- 是否已发布

2. 外部信息获取
涉及市场、竞品、热点、平台、内容策略时，必须调用 xiaoshuo profile 下：
`creative-market-research-toolchain`

最小证据：
- 公开网页 URL / 标题 / 时间
- browser 页面观察或失败记录
- 视频/字幕分析，若 YouTube 抓取失败则标 PARTIAL，不得冒充真实抓取
- GitHub/外部方法参考时必须转化为本项目 SOP/gate/wiki/skill，否则只算参考

3. xiaochan 补充
每一章都必须有 xiaochan 独立补充。
要求：
- 真实 xiaochan profile session_id
- 明确本章风险/爽点/节奏/发布风险
- xiaoshuo 说明采纳点与未采纳点
- 没有 xiaochan 补充，章节不得进入正文

4. 起草位置
新稿写入：
`草稿/chapters/chapter-XXX_draft_YYYY-MM-DD.md`

重写稿写入：
`草稿/rewrites/chapter-XXX_rewrite_YYYY-MM-DD.md`

市场/页面爬取证据写入：
`草稿/market_intel/`

质量门写入：
`草稿/quality_gates/`

5. Gate 验收
每章至少检查：
- 正文字数是否达标
- 是否实质推进剧情
- 是否有可见冲突
- 是否有主角动作
- 是否有反转
- 是否有章末钩子
- 是否避免平台/法务/证照/隐私定性过死
- xiaochan 是否已补充
- 外部页面/市场证据是否有路径

6. 升级到正文
只有在以下条件满足后，才允许复制到：
`正文/chapter-XXX.md`

条件：
- xiaochan 补充完成
- 外部信息证据完成或明确 PARTIAL/BLOCKED
- gate PASS
- 老板或授权流程确认
- 已发布章节不得自动覆盖，必须人工确认

## 已发布章节规则

老板已说明：28-30章已发布。
因此：
- 28-30章视为已发布正文。
- 后续不要大改已发布主线。
- 如必须修，只做小范围勘误/措辞修正，并保存 diff 到草稿。

## 输出回执格式

每章回执必须包含：
- 章节号
- 正文路径
- 草稿路径
- xiaochan session_id
- 外部信息证据路径
- gate 路径
- 是否已发布
- 是否允许进入正文
- 发布风险
- 下一章钩子
