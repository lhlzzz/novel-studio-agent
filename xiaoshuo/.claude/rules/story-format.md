# Story Format Rules

正文文件的格式规范。当用户直接编辑正文文件时自动加载。

## 绝对禁止

1. **禁止一句一行、短句堆砌**：叙述段不能像提纲、脚本或试写碎片。
2. **禁止系统说明书化**：系统提示必须像账单、判决、死亡通知或错误日志，不能替代人物行动。
3. **禁止情绪爆点全用句号压平**：崩溃、反转、暴怒、惊惧处要有自然停顿、破折、反问或感叹。
4. **禁止人物功能化**：角色不能只负责递线索、解释规则或制造追杀。
5. **禁止跳出视角**：已确定视角后，不切换到其他角色内心。

## 格式规范

- 以自然段承载连续动作、感受、环境、心理和信息推进。
- 对话可以短，但叙述段要有段落密度和流动感。
- 按新动作、新物件、新信息、新对话断段，避免机械一行一句。
- Markdown 正文段落之间保留一个空行，不连续空多行。
- 章节标题用 `# 第XXX章 章名` 或项目既有格式，保持同书统一。

## Examples

### Correct — 自然段承载动作和情绪
```
林川站在门口，没有立刻进去。屋里一股久没人住的灰味，混着旧木头和潮气扑面而来，桌角那张过期外卖单还压在原处，像有人替他把三个月前的狼狈原封不动留着。

他弯腰去摸床头柜背面，指尖碰到一块凸起。薄木板“啪”地松开，里面藏着一个小纸盒，盒盖上写着三个字：第一个bug。
```
同一镜头内的动作、环境和心理被自然织在段落里，读起来不是短句清单。

### Wrong — 一句一行碎片化
```
林川站在门口。
他没有进去。
屋里很久没人住。
他闻到灰味。
他看见外卖单。
他觉得狼狈。
```
信息被切碎成提纲，缺少自然段流动。

### Correct — 对话用动作和关系温度引出
```
苏念把B超单推到他面前，指尖在纸边停了一下。

“六周。”

林川看着那张单子，喉咙像被什么堵住。
```
动作、物件和沉默共同承担情绪，不需要频繁使用“他说”“她道”。

### Wrong — 系统说明书化
```
系统说明：修复现实bug可以获得寿命和现金，但会付出记忆代价。宿主需要根据收益和代价做出选择。
```
这类表达像规则文档，不像小说现场。

### Correct — 系统账单化
```
【修复账单】
本次收益：寿命 +7 天。
本次扣除：苏念相关记忆永久删除。
风险提示：关系链完整度下降至 43%。
```
提示像账单或判决，能服务压迫感。
